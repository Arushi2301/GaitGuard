# GaitGuard Frontend
 
React Native (Expo) mobile app for **GaitGuard**, a smartphone-based movement screening tool for athletes.
The user records or uploads a short movement video; the app sends it to the GaitGuard backend, which runs
MediaPipe pose estimation and returns knee-angle measurements that the app displays and saves.
 
> GaitGuard is a screening tool only. It does not provide a medical diagnosis.

## Features
 
### Start and authentication
- **Splash screen:** animated pastel background with a walking pose skeleton, a frosted glass card
  ("Welcome to GaitGuard") and a short welcome sound (can be turned off in Settings).
- **Welcome screen:** Log In / Create Account.
- **Register:** name, email, optional mobile number. Password can be:
  - **Created by the user**, with a strength meter (Weak / Medium / Strong), or
  - **Generated by the app** (14 characters, copy and regenerate buttons).
- **Login:** with **email or mobile number** + password.
- **Forgot Password:** explains recovery options and opens an email to support.
- **Continue with Google:** button present, shows "Coming soon".
### Navigation
- **Top bar:** profile photo (or initial) with "Hi, Name" → opens Profile; 🔔 Notifications with unread badge; ⚙️ Settings.
- **Bottom tab bar:** Home · Analyze · History · Progress.
### Analysis flow
1. **Analyze tab:** choose a movement. Squat is available; Walking and Drop Jump show "Coming soon".
2. **Capture:** filming guide, "Please use the back camera" notice, Record or Upload.
3. **Record:** back camera only, 1080p, 3-2-1 countdown with tick sounds, framing guide, 0-15 s timer and an end beep. Recording is always
   exactly **15 s** and cannot be stopped early; Cancel discards it.
4. **Upload:** videos longer than 15 s are allowed, with a notice that only the first 15 s are analyzed.
5. **Preview:** plays the clip with a quick checklist; Analyze or Retake.
6. **Result:**
   - Left and right knee cards: **average depth** (mean of per-rep minima) or **deepest point** if the
     backend used its fallback; knee bend (180° − angle); "Not measured" when a leg was not visible.
   - Rep count and depth per rep.
   - Explanation and scientific notice.
   - Error states with retry tips.
   - Successful results are **saved to history** and a **notification** is created.
### Settings
- Appearance: Light / Dark theme
- Sounds & Alerts: welcome sound, notifications
- Server: backend address with **Save & test connection**
- Data: clear analysis history
- Support: Help & Support, About
- Log out
Recording length and camera were **removed from Settings**: recordings are always 15 s, and
only the back camera is used (front-camera video is mirrored and would swap left and right legs).
 
### Profile
Photo from gallery, name, mobile, age, height, weight, fitness level, preferred sport, goals.
Shows **BMI** calculated from height and weight. Email cannot be changed.
 
### Notifications
In-app list per account: analysis complete, analysis failed, announcements. Mark read, mark all read,
long-press to delete, clear all. Respects the Notifications setting.
 
### Help & Support
How-to steps, recording tips, FAQs, contact support, report a problem.

## Setup
 
Requirements: Node.js (LTS), the **Expo Go** app on your phone (SDK 57), and the backend
(see `../backend/README.md`).
 
```bash
cd frontend
npm install
```
 
Run `npm install` again after every pull that changes `package.json`.
 
## Run
 
1. Turn on your **phone hotspot** and connect the laptop to it.
   College/hostel Wi-Fi blocks phone-to-laptop traffic.
2. Start the backend (in `backend/`):
```powershell
   .\venv\Scripts\Activate.ps1
   python -m uvicorn main:app --host 0.0.0.0 --port 8000
```
3. Start the app (in `frontend/`):
```bash
   npx expo start -c
```
   Scan the QR code with Expo Go.
4. In the app: **Settings → Server**, enter `http://<laptop-ip>:8000` and tap **Save & test connection**.
   Find the IP with `ipconfig` (IPv4 Address of the Wi-Fi adapter).
 
`src/constants/config.ts` holds only the **default** server address; the address saved in Settings is
used at runtime.

## Backend contract used
 
`POST /analyze` (multipart): field `file` (video), optional `movement` (default `squat`).
The `Content-Type` header is not set manually.
 
| Field | Used for |
| --- | --- |
| `status`, `reason` | success / error handling (via `screening.ts`) |
| `left_knee_min_angle`, `right_knee_min_angle` | deepest point per leg |
| `left_knee_mean_rep_min_angle`, `right_knee_mean_rep_min_angle` | average depth per leg |
| `left_knee_rep_min_angles`, `right_knee_rep_min_angles` | depth per rep |
| `rep_count` | reps detected |
| `rep_detection` | `fallback_overall_min` → label "Deepest point" instead of "Avg. depth" |
| `frames_analyzed`, `frames_with_pose` | tracking summary |
 
`null` angles are shown as **"Not measured"**, never as 0. Angles are interior knee angles
(180° = straight leg; smaller = deeper bend). Only the first 15 s of a video are analyzed.
 
### Member 3 Screening Assessment (`assessSquat`)

Screening assessment logic in `src/services/screening.ts` provides evidence-based kinematic screening:

#### 1. Function Specification & Interface

```typescript
export function assessSquat(
  measurement: ValidatedMeasurement | Record<string, any> | null | undefined,
  repStats?: RepStatsInput | null
): SquatAssessment;
```

**Return Type (`SquatAssessment`):**
- `depthCategory`: `'Deep' | 'Parallel' | 'Half' | 'Shallow' | 'Unmeasured'`
- `asymmetryDegrees`: `number | null` (absolute bilateral difference in degrees, or `null` if unilateral/invalid)
- `flags`: Array of screening flags (`'rep_mean_depth_used'`, `'fallback_depth_used'`, `'single_leg_visible'`, `'asymmetry_noted'`, `'insufficient_reps'`, `'unsupported_movement'`, `'depth_unmeasured'`)
- `summary`: Plain-language, non-diagnostic observational summary
- `sources`: Published sports-science reference citations
- `evaluatedKneeAngle`: Evaluated interior knee angle in degrees (`180°` = straight leg)
- `clinicalFlexionDegrees`: Clinical knee flexion equivalent in degrees (`180° - interior angle`)
- `depthSource`: `'mean_rep_min'` (preferred) or `'overall_min'` (fallback)
- `leftDepthAngle` / `rightDepthAngle`: Per-leg evaluated angles
- `deeperSide`: `'left' | 'right' | 'equal' | null`
- `repetitionSpreadDegrees`: Observed spread across valid per-repetition minima

#### 2. Depth Category Boundaries & Scientific Literature

Depth categories are mapped using backend interior knee angles and converted clinical flexion (`clinical = 180° - interior`):

| Depth Category | Interior Angle Range | Clinical Flexion Range | Published Citations |
| --- | --- | --- | --- |
| **Deep** | `<= 70.0°` | `>= 110.0°` | Escamilla (2001), Hartmann et al. (2013) |
| **Parallel** | `70.1° – 90.0°` | `90.0° – 109.9°` | Escamilla (2001), Schoenfeld (2010) |
| **Half** | `90.1° – 120.0°` | `60.0° – 89.9°` | Escamilla (2001), Caterisano et al. (2002) |
| **Shallow** | `> 120.0°` | `< 60.0°` | Escamilla (2001) |
| **Unmeasured** | Missing / non-finite / out of range | — | Handled safely without defaulting to 0° |

**Depth Priority:**
- When valid per-repetition minima are available, the mean of rep minima is preferred (`depthSource: 'mean_rep_min'`, flag `rep_mean_depth_used`).
- If repetition data is unavailable, the backend overall minimum is used as a fallback (`depthSource: 'overall_min'`, flag `fallback_depth_used`).

#### 3. Bilateral Asymmetry Evaluation & Single-Camera Limitations

- **Calculation:** Absolute difference `|left - right|` is computed **only** when both legs have valid measured angles.
- **Single Leg Visible:** If only one leg is visible, asymmetry is set to `null` and flagged (`single_leg_visible`), with an explicit note in the summary.
- **Perspective Caveat:** A flag (`asymmetry_noted`) is added when asymmetry is `>= 10.0°`, accompanied by an explicit reminder that in 2D single-camera lateral video, camera angle, perspective projection, and far-leg occlusion naturally introduce apparent asymmetry. No arbitrary clinical normal/abnormal thresholds are applied (Bishop et al., 2018).

#### 4. Sports-Science Citations

- **Escamilla RF.** (2001). Knee biomechanics of the dynamic squat exercise. *Medicine & Science in Sports & Exercise*, 33(1), 127–141. DOI: [10.1097/00005768-200101000-00020](https://doi.org/10.1097/00005768-200101000-00020)
- **Schoenfeld BJ.** (2010). Squatting kinematics and kinetics and their application to exercise performance. *Journal of Strength and Conditioning Research*, 24(12), 3497–3506. DOI: [10.1519/JSC.0b013e3181bac2d7](https://doi.org/10.1519/JSC.0b013e3181bac2d7)
- **Hartmann H, Wirth K, Klusemann M.** (2013). Analysis of the load on the knee joint and vertebral column with changes in squatting depth and weight load. *Sports Medicine*, 43(10), 993–1008. DOI: [10.1007/s40279-013-0073-6](https://doi.org/10.1007/s40279-013-0073-6)
- **Bishop C, Turner A, Read P.** (2018). Interlimb asymmetries: Understanding how to calculate differences from bilateral and unilateral tests. *Strength and Conditioning Journal*, 40(4), 1–6. DOI: [10.1519/SSC.0000000000000371](https://doi.org/10.1519/SSC.0000000000000371)

#### 5. Non-Diagnostic Language & Limitations

- GaitGuard provides informational movement screening and kinematic observation only.
- It does not diagnose musculoskeletal conditions, predict injury risk, or assess exercise safety.
- Users experiencing discomfort or functional concerns are directed to consult a qualified sports-medicine professional.
- Movement scoping: squat-specific assessment is strictly restricted to supported squat movements (`movement === 'squat'`).

## Data storage
 
Everything is stored **locally on the phone** with AsyncStorage (no auth server yet):
 
| Key | Contents |
| --- | --- |
| `gg.users` | accounts (passwords stored as SHA-256 hashes) and profiles |
| `gg.session` | logged-in account |
| `gg.history` | saved results, tagged with the account email |
| `gg.notifications:<email>` | notifications for each account |
| `gg.settings` | app settings |
| `gg.themeMode` | light / dark |
 
Videos are sent to the backend only for analysis and are not stored by the app.

## Known limitations
 
- Accounts exist only on the device; there is no password reset by email.
- Google sign-in is not implemented yet.
- Only squat is analyzed; other movements are marked "Coming soon".
- Phone and laptop must be on the same network.
- Expo Go shows its own grey ⚙️ developer button on screen; it is not part of the app.
